How the pipeline checks this page

After uploading, the workflow downloads the live page and looks for one specific word inside it:

curl -sf https://YOUR-SITE/ -o page.html
grep -q "SITE-OK" page.html

Marker found → deploy succeeds.
Marker missing → deploy fails and the old version is restored.

Try it yourself

  1. Change VERSION 1 above to VERSION 2, commit and push. Watch the pipeline go green, then reload the live site — you should see version 2.
  2. Now break it on purpose. Find the <!−− SITE-OK −−> comment near the top of this file and delete it. Push again.
  3. Watch the deploy fail, then watch it put version 2 back by itself. The live site never shows the broken page.
  4. Put the marker back to return to normal.

Why the marker is written oddly on this page

The check is a plain text search, so it matches the marker anywhere in the file — including inside ordinary sentences. If the name were spelled out normally in the text above, deleting the real marker would still leave matches behind, and the health check could never fail.

So every mention on this page except the real marker is written as SITE&#45;OK. The browser shows a normal hyphen; grep sees something different. That keeps exactly one match in the file.

Check it for yourself: grep -c "SITE-OK" sample.html should print 1.
